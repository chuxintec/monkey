# Optional Codex CLI C# post-processing

当前 v0.6 交付必须使用[全量项目批处理](CODEX-PROJECT-POSTPROCESS.md)实际跑完完整manifest C#。本文的独立小选择接口保留兼容和单批执行用途；过去两方法调用只是接入证据，不是全量交付。每个批次独立预算/session，整个项目不受“只一次调用/恢复”限制。


This module wraps one bounded local `codex exec` pass after deterministic C# export. It is opt-in and is not called by ordinary export/convert operations. The original candidate and its owning `manifest.json` remain immutable; every run creates a new revision directory with a copied workspace and a machine-readable revision `manifest.json`.

## CLI

After ordinary `convert` or `code-draft` has finished, explicitly select a small module:

```sh
monkey code-postprocess --candidate /path/to/candidate \
  --expected-manifest <sha256> --selected-path SourceRecovery/CSharp/<source>/Unclassified/Rules.cs \
  --task-file /path/to/task.txt --evidence-root /path/to/bounded-evidence \
  --evidence-file source-fragments.json --out /path/to/new-revision \
  --budget-seconds 900 --idle-seconds 180
```

Repeat `--selected-path` for related generated files. `--prepare-only` prepares and verifies without starting a model session (local CLI help is probed). Checkpoints use `monkey code-postprocess-resume --run /path/to/revision --session <exact-uuid>`. Normal export never invokes this command automatically.

## API

`prepare(candidate_root, selected_files, expected_manifest_sha256, output, task, *, evidence_files=(), evidence_root=None, context_files=(), context_root=None, project_batch=False, project_result_ledger=False, max_resumes=1, codex=..., timeout_seconds=900, no_progress_seconds=180, max_output_bytes=..., max_input_bytes=..., max_workspace_bytes=...)` verifies the exact candidate manifest, requires every selected path to be a manifest-owned generated `.cs` file, validates per-file hashes, then copies selected files into `output/workspace/`. It also saves a mode-restricted before copy, initializes a fresh Git repository with no remote or commit, hashes the requested/resolved Codex executable, and stores minimal `exec resume --help` capability evidence. The destination must be new and separate from the candidate and evidence roots. Copies are independently allocated and verified; no hard links are used. `project_result_ledger` defaults to false and requires `project_batch=True`; existing inline `fileResults` behavior is unchanged by default.

The legacy `evidence_files` interface remains available for non-batch calls and embeds bounded UTF-8 excerpts in the prompt. Batch calls treat `evidence_files` as read-only context files for compatibility. New callers can pass `context_files` and `context_root` directly; context is copied without hard links into `workspace/__Context/`, with write bits removed and hashes recorded, then referenced by path in the prompt. Context contents are not embedded in the prompt. The post-run integrity check rejects changed context bytes or permissions, extra files, symlinks, and hard links. The selected generated C# is the only writable source content.

With `project_batch=True` and the default `project_result_ledger=False`, the response schema adds a required `fileResults` array. Each selected file needs a separate result with `path`, `status` (`processed`, `unchanged`, `partial`, or `blocked`), a concrete `summary`, `unresolved`, `membersReviewed` source identifiers (empty is allowed when stable identifiers are unavailable), and `originalLogicPreserved`. Missing rows are recorded as `blocked` in the revision and prevent a complete result. Filename-only member entries and generic summaries do not count as processed. The parent queue remains responsible for comparing reviewed member identifiers against its source-function mapping.

With both `project_batch=True` and `project_result_ledger=True`, the same per-file schema is written to the one additional workspace path `__Reviews/file-results.json`; the final response instead requires `fileResultsArtifact` equal to that exact path and keeps the usual top-level `status`, `changedPaths`, `unresolved`, and `summary`. The prompt makes clear that the ledger only shortens response serialization: every selected source file still requires actual analysis, and reviewed source IDs can be copied from read-only mappings after that review. Unreviewed or missing files must be `blocked`; `partial` is for a reviewed file with a concrete unresolved issue or semantic difference, and `originalLogicPreserved` must accurately report that difference. The wrapper parses the ledger as bounded UTF-8 JSON (16 MiB and 1,000,000 nodes), runs the same file-result validation as inline mode, and archives the raw bytes under an attempt-specific `file-results-ledger-NN.json` with SHA-256 and byte count in the revision manifest. The precise ledger file and its `__Reviews` parent directory are the only workspace-boundary exceptions; the ledger is excluded from code changes and unified diffs. Symlinks, hard links, extra files, malformed rows, missing ledgers, wrong artifact references, or declaring the ledger in `changedPaths` cannot count as processed or complete. `fileResultsArtifactIssues` separately reports artifact structure/reference problems, while missing per-file rows remain per-file issues so other valid rows can be evaluated independently. Inline and normal valid-ledger runs return an empty artifact-issues array; a pre-start operator pause can report that no ledger was produced while retaining the prepared revision. Read-only source context continues to be hash-checked.

`max_resumes` sets a per-batch resume cap; it defaults to 1 for the legacy API and can be set to 2 for batch work. `timeout_seconds` is cumulative child execution time across resumes for that batch. Separate queue batches have independent limits; this module does not cap the project-wide session count.

`request_pause(prepared_root)` writes a fixed `control.json` record bound to that revision's `runId`; it cannot execute commands. For a running child, the worker observes the request, sends SIGINT to its own process group, waits up to 10 seconds, then escalates to SIGTERM/SIGKILL with bounded waits. It reports `outcome='operator_paused'` and `blockingCondition='operator_pause'` only after the child is confirmed exited, saves the session/checkpoint, and marks the control `acknowledged`. A pause requested before launch is acknowledged without spawning Codex; a later explicit `run(prepared)` consumes that pre-start control and proceeds. A completed or finalized child returns `pause_not_needed`. An exact-session `run(prepared, session_id=...)` consumes an acknowledged pause before resuming, so the same pause cannot immediately stop the resumed attempt. Operator pause is distinct from quota/auth/permission blockers.

`configure_checkpoint(prepared_root, timeout_seconds=..., no_progress_seconds=...)` changes only those two finite budgets (cumulative timeout is limited to 3600 seconds and idle must be positive and no larger than timeout). It is allowed before any child has started or after an exited checkpoint, never while a child is active. The request and revision record old/new values and preserve `childElapsedSeconds`, `resumeCount`, and `maxResumes`; the new cumulative timeout must exceed elapsed child time. Older prepared revisions without a `runId` receive a stable derived identity from their existing root/base/selected/task/executable pins, with an `identityMigration` receipt; no source pin or counter is reset. The worker never adjusts an active process.

`run(prepared, *, session_id=None, codex=None)` invokes the configured local CLI with an argument array and the prompt on stdin. Initial runs use:

```text
/opt/homebrew/bin/codex exec -C <workspace> --sandbox workspace-write --json \
  --output-schema <output-schema.json> -o <final-response.json> -
```

The installed CLI is `codex-cli 0.162.1` as observed during implementation. On this version, `exec resume --help` includes `--output-schema`, `-o`, and `--json`; the compact capability record and help-output hash are saved in each prepared revision. The wrapper does not set a model, profile, global configuration, or credentials; the existing local configuration is inherited. Model, reasoning effort, and usage are extracted only from safe JSONL fields when present, otherwise recorded as `unknown`.

The first invocation is serialized by a process-wide file lock. `process.json` records child PID and running/exited state; a small process-wide active record also prevents another batch starting if the parent is interrupted. A still-running or uncertain recorded child is never killed automatically. There is no nested CLI/agent execution. Total-time, no-event, and combined event/stderr-output budgets stop the child and preserve its checkpoint. Workspace size is verified at exit; an over-budget workspace is classified partial/failed and oversized files are not loaded for a textual diff. A resume within the remaining cumulative child-time budget is allowed only with the exact UUID reported and saved in that batch; `--last` is never used. A checkpoint workspace is hash-checked before resuming, so a manual edit requires a new reviewed preparation instead of being silently overwritten.

## Results and limits

`manifest.json` in the revision directory records the base manifest identity, selected paths/hashes, context hashes, before-copy identity, per-file results for batch work, observed workspace changes, unified diff path/hash, unresolved items, process exit, session when visible, event log location, Git boundary, safe model/effort fields, and turn usage when present. Only typed `error`, `turn.failed`, or `item.type=error` JSONL events and clearly prefixed CLI stderr error lines can set `blockingCondition` to `quota`, `auth`, or `permission`; the revision carries a fixed safe summary without raw error text. Tool output and source contents are never scanned for blockers. `events.jsonl`, `stderr.log`, the before copy, and the final response remain local to the private output. Candidate manifest and selected-source hashes are checked again after the CLI exits.

`complete` means the CLI exited zero, returned a response with exactly the required fields, declared exactly the paths in the actual diff, changed only selected files in place, and left no unresolved items. Added/deleted paths, symlinks, hard links, extra workspace files, changed source inputs, a changed Git boundary, and malformed responses cannot be complete. It is not proof of compilation, correctness, runtime behavior, or adoption. A partial response, unresolved item, timeout, or nonzero exit is `partial` when edits exist and `failed` otherwise. Unexpected files and edits are recorded; they are not promoted into the original candidate. A finished revision is immutable to this wrapper; subsequent work uses a new output directory.

The subprocess is launched with `shell=False`, `--sandbox workspace-write`, and no approval bypass options. The wrapper does not read credentials, use other AI services, run source JavaScript/WASM/DLL, modify the original owning manifest, or write a formal game project.
