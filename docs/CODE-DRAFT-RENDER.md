# Acorn-to-C# method drafts

`monkey.code_draft_render.render_method(method, ast, source_bytes, *, class_name=None)` converts one source-bound Acorn method AST to a best-effort C# method declaration. It is a syntax-oriented draft renderer: it does not execute JavaScript, instantiate Cocos, infer a closed type system, or claim behavioral equivalence. The result contains `source` (the declaration without file-level `using` directives), `usings`, `diagnostics`, `approximateTypes`, `members`, `emittedName`, the supplied byte span, `sourceExecuted: false`, and `draftOnly: true`.

`render_field(field, ast, source_bytes, *, class_name=None)` uses the same expression renderer for one source-bound field initializer. It emits a `dynamic` field declaration, preserving supported literal/object/collection initializers. If the initializer AST is absent or unsupported, it preserves an escaped source fragment, records a named diagnostic, and emits an explicit `NotImplementedException` at initialization rather than inventing a default value.

The method record must supply `name`; it may also supply UTF-8 byte `sourceBytes`, its matching `sourceSha256`, `parameters`, `static`, `access`, and `async`. When both span and hash are present, the renderer checks them against the exact source byte slice. The AST may be a `FunctionExpression`, `ArrowFunctionExpression`, `FunctionDeclaration`, `MethodDefinition`, or direct `BlockStatement`; its `start` and `end` offsets are UTF-8 byte offsets from Monkey's Acorn bridge. The complete original source is passed as bytes so diagnostics can cite exact spans and unknown nodes can retain a small escaped source excerpt. Parent code owns class grouping, global name disambiguation, file layout, and coverage accounting.

The renderer handles ordinary expressions and control flow directly: local declarations, assignments and updates, calls, `if`, `switch`, counted and conditional loops, `for-in`/`for-of`, returns, throw, try/catch/finally, arrays, object literals, strings/templates, lambdas, common Math calls, and a small set of `cc.log`/`warn`/`error`, `cc.isValid`, `cc.v2`/`v3` draft mappings. It uses `dynamic` for values without trusted types. Cocos logging maps to Unity logging; `Math.random` maps to `UnityEngine.Random.value`; these are explicitly approximate. `cc.isValid` becomes a null check and does not model Unity destroyed-object semantics.

Unknown syntax is handled locally. In an expression it remains as an escaped comment and a reached `NotImplementedException` placeholder; later sibling statements still render. An unsupported statement is retained as an escaped comment with a named diagnostic. A source-backed empty `BlockStatement`, including a body containing only empty statements/blocks (comments do not appear in Acorn's executable AST), is emitted as `return null;` to model JavaScript's implicit undefined result. The empty-body proof uses bounded iterative traversal; cycles, malformed bodies, and budget overflow are not treated as empty. A nonempty body that loses all executable statements to unsupported syntax still gets an explicit `NotImplementedException`; it is not mistaken for an empty source method.

JavaScript coercion/truthiness, prototype inheritance, `undefined`, sparse arrays, object shape mutation, property descriptors, iterator/promise behavior, dynamic Cocos APIs, and source lifecycle contracts are not generally reproduced. They are named in diagnostics or method-level metadata. Several constructs may produce C# syntax/API errors, especially unknown source-shaped calls, dynamic switch labels, unusual operators, static `this`, or unsupported destructuring. The code is a draft for review and completion; it must not be counted as compiled or behaviorally verified based on rendering.

The renderer itself accepts one supplied method AST at a time; it neither reparses a file nor selects methods. It contains node/depth limits. A caller that cannot provide a method AST should emit its own visibly incomplete fallback while continuing to account for that source method. The tests use both explicit AST fixtures and a real local Acorn parse, and assert generated C# content plus local-failure continuation; they do not compile or run recovered game code.

For source declarations with multiple local names, the draft emits one `dynamic` type followed by comma-separated declarators. `for` initializer declarations use the same form; assignment and increment expression statements are unwrapped to C# statement-expression syntax. Unmapped `this` in a static method or field initializer retains its receiver text and receives a diagnostic; a resolved static-owner member mapping does not retain that source receiver.

When an expression statement needs a generated discard, the renderer declares a uniquely named `__draftDiscardN` local after reserving all identifiers from the method AST, including nested closures and mapped targets. Actual source assignments such as `_ = value` remain assignments to the source identifier; generated discard handling does not use `_` or rewrite source text.

AST nodes may carry `_draftIdentifierTarget`, `_draftMember`, and `_draftUnresolvedMember` annotations from the parent symbol planner. Safe identifier targets are used at references and declarations. A resolved static member emits `OwnerClass.Target`; a resolved source member keeps its original receiver and substitutes only the member target. An unresolved member keeps its original receiver/name and emits a named diagnostic. The renderer does not globally rewrite `this`. Standard global names such as `Array`, `Map`, `Set`, `Math`, and `cc` are treated as builtins only when the AST has no lexical `bindingId`, so a shadowing local remains a local symbol.

For an unresolved member whose source receiver is known to be a static owner, the planner may place `_draftStaticThisOwner` on its `ThisExpression`. A safe qualified owner replaces only that direct receiver (`OwnerClass.unknownMember`, without receiver parentheses); the unresolved-member diagnostic remains, and the property name is not guessed. Computed members retain their original computed access. Unannotated dynamic `this` is preserved unchanged.

The collection constructor subset evaluates supplied arguments once and in source order. `Array()` creates an empty list, one numeric argument is treated as a length (integral values from 0 through 1,000,000 are supported), one nonnumeric argument is one element, and multiple arguments become list elements. A length expression uses LINQ to fill null slots; JavaScript sparse-array and coercion details remain approximate. `Map(iterable)` and `Set(iterable)` enumerate their first argument into a dictionary or hash set; a null source evaluates once and yields an empty collection. Their ordering, equality, duplicate-key behavior, and JavaScript iterator protocol can differ. Unknown/spread collection shapes evaluate arguments into locals and then throw `NotImplementedException`; they do not silently discard arguments or manufacture an empty collection.

Builtin lowering requires an unbound, non-ambiguous identifier. If a node is marked `bindingAmbiguous`, names such as `Array`, `Math`, `cc`, `undefined`, `NaN`, and `Infinity` remain source-shaped instead of being assumed global builtins.

Nested function and arrow nodes carrying a safe `draftFunctionId` include a `/* source-function:<id> */` marker at their emitted location and appear in the result's `embeddedFunctions` list. The top-level method being rendered is never reported as embedded. A method's optional `captureParameters` list appends safe `dynamic` capture parameters not already present in its signature; duplicate captures are emitted once. These annotations provide source-to-draft placement evidence and do not validate closure behavior.
