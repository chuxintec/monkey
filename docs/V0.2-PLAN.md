## 1. 产品行为与当前差距

入口仍是一条`convert`：明确原包/输入集合→获取已声明远程依赖→来源识别和解析→typed中间数据→目标原生工程与可接续代码→可选格式化→分层核对/接续材料。源文件只读，目标默认新目录；未知版本/缺源有明确结果，不复制整个包当“兼容”。

Cocos来源输出Unity6、Creator3.8.8或both；Unity（包括团结分支）、Laya/LayaAir、Egret、自研及其他来源统一输出Unity6，非Cocos请求both/Creator直接拒绝。支持范围是逐profile的真实证据，不能从一个引擎版本字符串泛化全版本。

v0.1仅Cocos2.4.15结构子集；full14资源原生出口实际完成，两端各1694独立Prefab/24784节点强回读零诊断。914代码文件仍是占位初稿、不是业务恢复；动态行为、Spine播放、原版视觉和真实交互仍独立未完成。v0.2不以同样空壳更名或文件数增长达标。

## 3. 分层与具体模块

复用v0.1的`inputs/containers/acquisition/package`安全输入、全文件账、缓存/哈希、签名、原名及目标导入器；不在每个游戏复制工具。新代码按家族隔离：

| 建议模块 | 职责/输出 |
| --- | --- |
| research_cases.py | 动态发现与冻结显式case清单；状态、源位置与隐私边界 |

| sources/cocos3.py / cocos_legacy.py | CCON/JS模块、UUID子资源、旧rawAssets/pack分别适配；不硬套2.4 parser |
| code_model.py / code_csharp.py / code_javascript.py | 统一语义事实→目标可编译/解析子集与明确待补接口；原源码映射 |
| project_model.py / formatting.py | typed资产路径、身份、地址键与所有权；格式预览/新输出应用 |
| target_unity_recovery.py | Unity来源的实际Unity6重建与验证，区别跨引擎uGUI生成合同 |

Unity不能强制转换成Cocos节点图。对象身份为`sourceDigest + serializedFileId + signed pathID(decimal string)`，外部PPtr的fileID按同一serialized文件外部表解释，GUID/fileID/pathID分列；全部64位ID用十进制字符串，不能通过JS number。源TypeTree缺失、版本模板、Mono实现和IL2CPP/Wasm/Lua方法体证据分开。使用现有固定provider，不重写Unity二进制生态、不安装全局工具、不执行未知程序集。目标真实Unity6格式处理/原生保存回读，不能只改ProjectVersion。

## 4. 可接续C#与TypeScript优先的Cocos代码

### 语义合同

CodeModel每个类/方法/字段包含原名、可用目标名及消歧理由、模块/导出、源整文件SHA/字节范围、依赖/调用/事件/资源键、推断类型及可信度。方法状态分为implemented-evidenced、signature-only、unparsed、unsupported；统计已转写方法/仅签名/待实现，保留原AST/IR对应关系。源码内容不作工具指令。

有限可证实子集先做：常量/DTO、算术及布尔、分支、明确定义字段读写和状态变化、同语义同步方法调用。JS Number/位运算/真假值/空值、求值顺序、异常、this/闭包和数组语义必须满足对应条件；不满足则保留原逻辑与具体端口待补。未知网络、奖励/支付、随机、异步和存档不能写默认成功替身。JSON仍为运行时唯一数值真源，不把表复制成可编辑SO字段。

### Unity交付

输出具名Domain模型/DTO与方法、Gameplay接口及用例骨架、Presentation View与实际序列化引用、Services端口及可证实适配、Bootstrap装配；职责确有证据才建目录。Prefab原组件引用/事件绑定映射到具体字段/方法，不能改为字符串解释节点图。可编译有据子集进目标Assets；待实现业务和反编译不完整源码在SourceRecovery并附接口、原文及AI任务，不靠删除所有未知代码声称整个业务编译通过。

Mono真实反编译与签名/IL2CPP方法体分别记证据；CODEPHPY或未知保护代码明确不能反编译，不造DLL来源。不得凭字段名生成奖励/规则。第一代表模块固定为肥鹅NumberLabel：整文件/模块SHA、initValue/getValue等方法、MainUi内5处真实引用、C#/TS优先、JS次选目标及异步/格式化未知接口详见V0.2-EXAMPLES.md。优先有据非空方法与原生接线，不宣称完整动画已转换。

### Creator TypeScript优先、JavaScript次选

用户最新修订（总监human01a169c9-28a9-7120-96b0-df9511be3764，已原生读取）为TypeScript优先、JavaScript次选。默认输出可接续`.ts`，提供`--cocos-code-language ts|js`（默认ts）的明确选项；保留模块名/导出/生命周期，使用Creator3.8.8本机支持的ES模块与组件注册合同；目标TS/次选JS、原JS证据、未处理代码分目录。不能只把原JS改后缀成TS或用any填空壳；字段/参数/端口按有据类型生成，未知类型用明确unknown及待实现契约，不能放宽类型检查冒充可运行。以真实代表组件验证导入、注册/绑定、资源/事件接线和关闭重开；不能只做node语法检查就叫Creator可用。

第一模块与Unity使用同一源事实，比较有据计算/状态/视图关系，分别验证C#编译及Creator TS类型检查/JS次选解析与原生注册。新来源另选一个原生恢复模块，不能全部只在合成数据验证。

### AI入口

每工程START-HERE列真实入口、构建/编辑器要求、可改目录与生成所有权、闭环任务/前置依赖、原方法→目标方法映射、资源引用和未知项。按模型/界面/服务闭环聚合任务；源码细节可追溯，不再大量同一个Invoke/NotImplementedException模板。

## 5. 可选后处理格式化

CLI建议：

```sh
monkey convert --source <package> --target unity6 --out <fresh> --format none
monkey convert --input-set <sources.json> --target both --out <fresh> --format grea
monkey format-project --project <owned-candidate> --profile grea --preview --out <plan-dir>
monkey format-project --project <owned-candidate> --plan <plan.json> --out <fresh-project>
```

默认none：导出后不执行额外格式阶段；保留v0.1原名/既有结构，不把none解释成取消安全命名或身份生成。grea仅在导出完成后作为独立阶段，新输出应用，失败保留已完成未格式化候选及错误结果；不可假称整个格式成功。native编排使用格式后的最终冻结manifest。旧recipe不含format按none；v0.1阶段签名不能静默复用于新算法，旧证据只读。

依据GREA维护源`grea-unity-standard`标准1.0.0的结构总览、目录与资产归类、脚本与生成契约，以及`grea-cocos/references/05-Cocos-工程与迁移.md`，只读引用不修改GREA。采用Bootstrap/Domain/Gameplay/Presentation/Services五层；Content按Prefabs、Config、Levels、Materials/Shaders、Images/Sprites、Models、Animations、Spine、Fonts、Audio真实类型归类，不把所有asset当Config、不造空框架。

ProjectModel将物理路径、源名、目标标识符、GUID/UUID/localFileID、主/子资源、导入设置、源对象/实例关联、逻辑加载key及bundle/address/Resources键分列。迁移计划列old/new、identity、before hash/meta hash、ownership、typed引用边、确定/动态key及冲突；数值JSON和资源原字节保持。源名不因目录移动改类/程序集/反射名。

离线尚未导入候选在typed生成层重排并重发精确引用，不做源码或任意JSON的全局字符串替换。已导入资产若纳入范围，必须用Unity AssetDatabase/Creator原生移动机制并复验，不能只在磁盘rename meta；首期可明确拒绝已有Library/导入态并给出native迁移未实现，而不能破坏工程。

人工/human及seed-once不覆盖，modified generated或未知文件冲突即阻止受影响操作；当前指纹与原计划不符标stale-plan。默认新输出保证原工程不变，不实现无回滚的原地模式。Resources之后原key不变、address/bundle别名保留；动态拼接/反射不可静态证明时保留原寻址或阻塞该移动，不能猜测替换。重名按真实类型/语义路径及稳定短ID消歧，拒绝穿越/符号链接/大小写和Unicode冲突。

格式化完成需同一身份集合、资源字节/JSON语义一致，Scene/Prefab实例关联和typed引用闭包一致，新增悬空引用0、动态key保留；双目标各有必要原生回读。默认none与显式grea的差异可预览且可重复，人工漂移被拒绝是必要反例。
