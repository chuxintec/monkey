# v0.5.0 开发：大工程复用与采用兼容快照

开发入口为 `.venv/bin/python -m monkey.cli`（0.5.0.dev1）；日常安装版仍是 v0.4.0。本文件保留 05-A 实现说明与 05-B **已冻结、待移交 beaver 的兼容实现**，整版其他工作包另见 PLAN。三方判断、原生采用及回滚不再是 monkey 新主线能力；快照/证据/接手限制见 [BEAVER-HANDOFF](BEAVER-HANDOFF.md)。beaver 替代尚未验证，不自动转发或移除原命令。

## 大工程预算与源阶段复用

完整输入候选的统一上限为 8 GiB / 500,000 文件，单文件 512 MiB，主清单 128 MiB / 800 万节点；选择子集仍为 256 MiB / 20,000 文件。清单不能自行提升这些上限。文件复制、备份和哈希按 1 MiB 块处理，避免一次把全部变更载入内存。源容器、像素、对象解析预算继续独立，不能用输出上限绕开解析限制。

`manifest.json` 与 Unity 来源的 `recovery-manifest.json` 使用同一受限快照读取层；未知文件、大小写/Unicode 碰撞、符号链接和越界路径拒绝。POSIX 采用有界缓存的 no-follow 目录描述符读取，缓存最多 128 个目录；不支持该方式的平台保留逐路径检查。文件内容仍逐项核对哈希。旧 `apply` 不隐式处理 Unity recovery 清单，明确要求走 `adopt`。

源阶段合同把 Cocos inspect/normalize 与目标布局/发射器分开，不再仅以工具版本号拒绝复用。合同包括真实解析文件、源 I/O 函数及预算常量、归一化依赖库版本；读取器变化使相关缓存失效，布局变化只重跑目标阶段。旧 v0.4 源阶段只接受逐文件相同和经过固定哈希核验的旧 I/O 合同，不是任意旧版本都能复用。

```sh
python -m monkey.cli convert --input-set inputs.json --target both \
  --namespace my-game --reuse-source-stages previous-conversion \
  --layout layout.json --out fresh-conversion --offline
```

原输入/阶段/块文件仍需核验，复用不表示跳过文件读取和哈希。Unity 沿已有 `--unity-reuse-inspection`、准备纹理和 provider 输出复用合同，读取器/schema/预算不变才接受；不会因 Cocos 目录代码变化重新启动 Unity 源 worker 或 AssetRipper。

## 冻结兼容接口：adopt 预览与执行

采用范围是目标的 Assets/assets 资产及 meta；生成清单的 manual/retained 文件不自动覆盖。目标 Packages/ProjectSettings、人工文件和未知资产保留，依赖版本不满足时给出冲突，不自动安装包或覆盖设置。SourceRecovery、Docs 与 Analysis 仍在完整冻结候选中单独保留，本命令不把这些目录当作资产同步到游戏工程。

首次采用须提供独立的共同生成基线，不能把当前开发目录自身当作生成基线。三方比较按 namespace + profile + GUID/UUID 进行，没有可证身份的资源不能随意跨路径合并。Unity 来源没有显式 namespace 时，首次可用 `--lineage my-game` 指定稳定的游戏命名空间；后续保存在采用状态中，输入包字节变化不会因此被误判成另一个项目。已有声明的 namespace 不能覆盖。

```sh
python -m monkey.cli adopt --candidate incoming/UnityProject \
  --baseline previous/UnityProject --target development-copy \
  --out adoption-preview

python -m monkey.cli adopt --execute \
  --plan adoption-preview/adoption-plan.json \
  --expected-plan <plan-identity.json 中的 SHA256> \
  --editor-path /path/to/existing/Unity --out adoption-transaction
```

预览只读目标，执行重新验证清单、所有候选文件、目标资产、项目依赖/版本和采用状态。实现算法的哈希也绑定预览；代码变化后必须重新预览。当前执行后端限 Unity 6000.6.2f1（前一 WIP 代表移动原生通过；最终新增目录/资产尚未原生验证），Creator 3.8.8 共享三方预览，原生执行适配尚未实现，不据此宣称 Creator 采用已通过。

- 源未变化：保留本地编辑或本地删除。
- 源变化而本地仍等于共同基线：可更新；路径变化通过 AssetDatabase.MoveAsset，导入后回读 GUID/localID。
- 双方都改、未知目标占位、GUID 冲突、人工移动：阻止执行，保留预览供明确解决冲突后重新生成。
- 源移除：保留原有资产并列出 retainedRemoved，不自动删除。
- 新资源：只在没有目标文件/身份冲突时创建，原生导入并回读。

临时 C# 辅助代码位于独立的 Editor 目录，运行后按内容与所有权核验清理。只启动工具自己拥有的限时 child，不关闭其他 Editor、不删除 Unity 锁文件。标记文件存在时先只读核对进程，由 Editor 获取实际 OS 锁；不能确定状态则停止。

每次执行有 before/after 文件、计划身份和事务日志。原生应用与独立重开分别验证改动资源的 GUID/localID，并比较最多 128 份未修改 Prefab/Scene 的直接依赖；全部已有资产文件仍逐项保护。该回读范围不等于全游戏运行、动态加载键或视觉通过。

## 恢复与重复采用

```sh
python -m monkey.cli adopt-recover --transaction adoption-transaction \
  --editor-path /path/to/existing/Unity

# 首次成功后使用保存在开发副本 .monkey/adoption/state.json 的共同生成基线
python -m monkey.cli adopt --candidate next/UnityProject \
  --target development-copy --out next-preview
```

回滚仅还原事务内记录的资产和采用状态，经 Editor 恢复 GUID；完整事务之后有新的开发改动则拒绝覆盖。方法进入前失败时，核对受影响路径的 before-image 后才认定零写入；已进入方法的失败保留日志与 before-image，未知/后续改动标为 recovery-required，不用整体 reset 或删除 Library 恢复。新增空目录只在记录了原生创建身份且仍为空时清理，其他内容保留。

同一生成重复预览应产生 0 个资产操作；已有人工改动保持原样。重命名不自动重写源运行时中的字符串加载键，目录地址变化仍需既有映射和后续代码/加载适配；资源身份回读不能代替这项业务验证。
