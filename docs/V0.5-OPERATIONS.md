# v0.5 恢复侧操作与验收边界

本页描述本地 `0.5.0.dev1`，日常已安装版本仍是 `0.4.0`。从开发 checkout 使用 `.venv/bin/python -m monkey.cli`，或使用经核验的隔离 wheel 环境；本轮没有全局安装。完整候选预算和阶段复用见 [预算验收](validation/2026-10-26-v050-budget-reuse-handoff.md)。开发工程采用归 beaver，monkey 的 `adopt` 等入口仅作已冻结的弃用兼容，见 [交接](BEAVER-HANDOFF.md)。

## 显式补取和续接

```sh
monkey acquire-resources --manifest remote.json --input-set inputs.json --out acquired-01 --max-attempts 3
monkey acquire-resources --manifest remote.json --input-set inputs.json --resume-from acquired-01 --out acquired-02
monkey convert --input-set acquired-02/input-set.json --target unity6 --out candidate-02
```

只取得清单明确列出的 URL，不扫描 CDN 或猜测版本。最多 50,000 项、32 个 origin、4 路、每轮 1 GiB；单文件沿用 128 MiB，时间窗 30～3600 秒，预留 20 秒收尾。重试 1～3 次，仅限瞬态网络故障或 HTTP 408/429/500/502/503/504；重试下载也计入同一总字节/时间预算。404、内容哈希不符不重试、不造替代内容。重定向必须留在清单声明的 origin。

`--resume-from` 接受已经写出 `acquisition.json` 的**已结束部分成功层**，严格要求同一清单及 input-set SHA、同一完整请求集合/sourceKey。已物化载荷重核大小与 SHA 后复制进新的层，旧层只读；未完成项才重新尝试。它不是进程崩溃中途 journal 续传或 HTTP Range 断点下载。原输入内的缓存重新按声明 SHA 核验；没有声明 SHA 的下载标记为 `captured-bytes-without-declared-hash`，不能据此宣称匹配原厂版本。`--offline` 不发网络请求。无新增物化资源时返回原 input-set，读取 CLI 的实际 `inputSet` 字段。

## 诊断和处置

```sh
monkey diagnose --source candidate --out diagnostics
monkey diagnose --source typed-objects.json --evidence full-resource-handoff.json --max-document-bytes 67108864 --max-issues 50000 --out diagnostics-expanded
```

索引既有解析、引用、获取和原生回执，不重新解析原包、不启动 Editor、不校验全部候选字节。每项有稳定 issueId、来源身份、证据文件 SHA、影响和下一步；只有容器 SHA + serialized file + pathId 完全匹配才接入已有目标路径/GUID/hash，且仍标记目标字节未重新核验。没有精确映射明确记为 `no-exact-target-in-selected-evidence`，不按文件名猜绑。

默认单文档 32 MiB，可显式 1 KiB～128 MiB；整轮 256 MiB；默认 2000 issue，可显式到 100,000。超出预算保留 deferred/omitted 和 `coverage.complete=false`。`complete` 仅表示本次选定文档读取/条目覆盖，不代表完整游戏恢复。巨型 dependency typed 分片须显式选择。原始回执中的旧限制和新代表读回分别保留出处，不自动用两份 Spine 证明清除全部 1776 份待验状态。

36 份样例项目失败正文仍隔离：19 Image、10 Text、3 TMP 类、4 自定义类。原生头 72 引用的保留不让正文变成 writable；必须取得精确 Unity 版本/平台/scriptId/typeHash 的可信 schema。借用树的已解析字段仍须 `unity-field-plan` 独立参考与精确目标身份门；不能凭成功解析自动写入。

## 原生资源代表

```sh
monkey resource-probe --candidate CocosProject --expected-manifest SHA256 --spine EXACT_SOURCE_ID --out spine-probe
monkey resource-probe --candidate CocosProject --expected-manifest SHA256 --shader EXACT_SOURCE_ID --out shader-probe
```

只支持已冻结 Creator 3.8.8 候选中标准 3.8.x、闭包完整的 Spine，1～16 个 ID、选中载荷最多 128 MiB。原骨骼/atlas/页图及 meta 哈希逐项核验后进入全新最小工程；不带原游戏层级或业务脚本。随后按现有 `native-import` 的显式 Editor/窗口/预算合同执行。保存重开读回校验骨骼 UUID、atlas 页名、页图/原生纹理 UUID，原生 AnimationState 的时间与实际骨骼姿态都需变化；只推进计时器不通过。静态姿态或特殊动画可被严格拒绝，不能据此推断原资源损坏。

已实测标准 3.8.99 的二进制和 JSON 各一份；8 份非标准改写版本不篡改版本号。本轮未安装 Unity Spine runtime，Unity 骨骼播放未验证。Shader 的精确程序/宏范围和编译/像素探针见 [SHADER-PROFILES](SHADER-PROFILES.md)，其他 Effect 仍保留原始源并等待适配。

Shader 选择同样绑定冻结 manifest、catalog 和原始 EffectDescription SHA。只生成隔离原生子集及独立 `NativeProbe/ShaderProbe`，CLI 返回明确的 probeProject/method；它不启动 Editor。图形设备上的 `MonkeyShaderProbe.Run` 与常规 native-import 是不同方法，不用无图形的批处理结果冒充像素验证，也不自动把该材质挂到游戏对象。

## 环境和空间

```sh
monkey doctor --out environment --unity-editor /installed/Unity --creator-editor /installed/CocosCreator --provider-python /installed/venv/bin/python
monkey space-preview --root outputs --protect /path/to/current-manual-content --out space-report
```

doctor 只读显式 Editor 的 macOS bundle 版本以及已安装 Python/依赖元数据；provider 为隔离 `-I -B` 的固定 metadata 查询，10 秒超时。Editor 未选择记为 not_checked。它不启动/安装 Editor，不代表项目连接、编译或可玩。

space-preview 扫描元数据，不删除；最多 50 万文件/50 万入口，跳过符号链接/特殊文件并记录不完整。只将具备已识别候选 manifest 的 Library/Temp/obj/Logs 列为可审阅缓存，存在 UnityLockfile 时继续保护。原包、SourceRecovery、Evidence、Assets、人工和未知内容保护；空间为逻辑字节，不能当作 APFS 克隆/硬链接后的实际释放量。清理需另外明确授权。

## 分发和 CI

`scripts/smoke_cli.py --python /isolated/venv/bin/python --out smoke.json` 从源码 checkout 外的临时目录运行已安装 wheel，核验 CLI 退出码、能力、模板分发、诊断分类和无删除行为，不调用游戏/Editor/真实 CDN。当前实际原生与隔离安装证据仅来自 macOS arm64；Linux/Windows 和 Python 3.11/3.14 的矩阵见 `.github/workflows/cli-smoke.yml`，未推送/运行远端 CI 前均为 pending，不能宣称平台全部通过。

工作流只读仓库权限、无发布步骤；Action 使用已查验的官方 [checkout](https://github.com/actions/checkout/releases/tag/v7.0.1) 与 [setup-python](https://github.com/actions/setup-python/releases/tag/v7.0.0) 版本。
